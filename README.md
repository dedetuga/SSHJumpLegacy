# SSH Jump (Legacy) — a browser SSH terminal as a classic ACAP for Axis ARTPEC‑4/5

A small **ACAP** (Axis Camera Application) that runs on older **MIPS** Axis cameras
(ARTPEC‑4 / ARTPEC‑5, AXIS OS 9.x, "classic" `package.conf` framework) and serves a
**browser SSH terminal**. It turns the camera into a tiny **jump host**: from the
camera's own web UI you open an `xterm.js` terminal and SSH into other devices on
the LAN (e.g. re‑adopt a UniFi switch). Idle sessions auto‑close and the app
auto‑stops after 30 minutes of inactivity.

Written in **Go**. As far as we can tell this is the only public example of a
classic‑ACAP Go app with a web terminal on ARTPEC‑4/5 — the path is undocumented,
so the notes below exist so it can be reproduced.

> **Scope / status:** ARTPEC‑4 and ARTPEC‑5 are end‑of‑life. This targets the
> classic framework (`package.conf`, no `manifest.json`). It installs over SSH
> with the device's own `install-package.sh`; it **cannot** be installed from the
> web UI on this hardware (see *Limitations*).

## Why this was hard (the four real blockers, and how each is solved)

| Blocker | What happens | Fix in this repo |
|---|---|---|
| **`elflibcheck.sh`** rejects the binary | The classic init script refuses to start anything that isn't an `ET_DYN` (PIE / shared‑object) ELF. Go **cannot** emit PIE for `linux/mipsle`. | The package‑root binary is a tiny **PIE launcher** written in freestanding MIPS asm (`launcher/`, generated by `build.sh`). It has no libc, no relocations, interp `/lib/ld.so.1`, so it *is* ET_DYN and passes the check — then `execve()`s the real Go daemon at `bin/sshjump`, preserving `argv`/`env` (so `pidof`/stop keep working on the name `sshjump`). |
| **Web transport** | The classic `control.cgi` mechanism (`mod_trax` + `TransferMethodProxy`) uses a **proprietary fd‑passing IPC ("fdipc")** where `mod_trax` wants to *bind* `/var/run/http/<app>/http` itself. Our listener collides with it → `do_transfer: fdipc_client_socket failed … errno 98` (EADDRINUSE), a silent Apache **500**. | We **bypass `mod_trax`**: the installer removes its transfer conf for our app and installs a standard **`mod_proxy_http`** rule (`packaging/zz_sshjump_proxy.conf`) that simply *connects* to the daemon's HTTP unix socket. The daemon also speaks FastCGI on the same socket (first‑byte sniff) for good measure. |
| **Apache doesn't pick it up** | A new app's proxy route only activates on a **full `httpd` restart**, not a reload. | `install-dev.sh` restarts `httpd`. |
| **Go MIPS hang (golang/go#71591)** | Go 1.23.0–1.24.0 static‑MIPS softfloat binaries spin at high CPU after hours. | Build with **Go ≥ 1.24.1** (fix included; verify `internal/runtime/` in `src/runtime/preempt.go`). |

Also handled: `STARTMODE=once` so the 30‑min idle exit isn't fought by respawn
(and the web stop/start toggle stays clean); Digest auth on `control.cgi`;
quiet logging by default (`SSHJUMP_DEBUG=1` for verbose tracing).

## Architecture

```
browser (xterm.js, /local/sshjump/config.html)
   │  fetch control.cgi?op=connect|poll|input|resize|close|health
   ▼
Apache httpd  ──(mod_proxy_http, Digest auth: axis-group admin)──►  unix:/var/run/http/sshjump/http
                                                                        │
                                                   ┌────────────────────┘
                                                   ▼
   /usr/local/packages/sshjump/sshjump   ← PIE launcher (ET_DYN, passes elflibcheck)
                                                   │  execve(), same PID, argv/env kept
                                                   ▼
   /usr/local/packages/sshjump/bin/sshjump  ← Go daemon: HTTP+FastCGI on the socket,
                                               golang.org/x/crypto/ssh bridge, idle watchdog
                                                   │
                                                   ▼
                                            SSH to a LAN device (e.g. 192.168.0.23)
```

Transport is HTTP long‑poll (not WebSocket): the Axis reverse proxy strips
WebSocket upgrade headers, so `poll`/`input` over plain HTTP is used instead.

## Build

ARTPEC‑4 (34Kc) and ARTPEC‑5 (1004Kc) are the **same build target** — MIPS32r2,
little‑endian, soft‑float, o32, `APPTYPE=mipsisa32r2el`. The Go daemon is static
(no libc) and the launcher uses no libc calls, so **one binary runs on both**;
`build.sh` just stamps the SoC into the output filename.

Requirements: **Go ≥ 1.24.1**, `gcc-mipsel-linux-gnu` (+ binutils),
optionally `qemu-user-static` for the smoke test.

```bash
./build.sh both        # → out/sshjump_1_0_0_artpec4_mipsisa32r2el.eap
                       #   out/sshjump_1_0_0_artpec5_mipsisa32r2el.eap  (identical payload)
./build.sh artpec5     # just one
./build.sh test        # build + qemu smoke test of the daemon
```

## Install (over SSH — the supported path on this hardware)

```bash
scp out/sshjump_1_0_0_artpec5_mipsisa32r2el.eap install-dev.sh root@<camera>:/tmp/
ssh root@<camera> 'sh /tmp/install-dev.sh'          # auto-detects the .eap in /tmp
```
The script ends with `http_status=200`. Then open
`http://<camera>/local/sshjump/config.html` (admin login) and connect.

## Configuration (environment variables read by the daemon)

| Var | Default | Meaning |
|---|---|---|
| `SSHJUMP_IDLE_TIMEOUT` | `30m` | Idle time before the app auto‑stops |
| `SSHJUMP_SOCKET` | `/var/run/http/sshjump/http` | Unix socket the daemon listens on |
| `SSHJUMP_LISTEN` | *(unset)* | If set (e.g. `127.0.0.1:2201`), serve plain HTTP on TCP for local debugging instead of the socket |
| `SSHJUMP_LOG` | `/tmp/sshjump.log` | Log file |
| `SSHJUMP_DEBUG` | *(unset)* | `1` = verbose tracing (every connection with hex dump, requests, watchdog ticks) |

## Layout

```
app/          Go daemon (main.go) + go.mod + vendored deps (x/crypto, x/sys)
launcher/     (generated at build time) freestanding MIPS PIE launcher
web/          config.html + xterm.js/css + addon-fit.js  → installed as html/
packaging/    package.conf, cgi.txt, param.conf, LICENSE, zz_sshjump_proxy.conf
build.sh      builds launcher + daemon, assembles the .eap (artpec4/artpec5/both)
install-dev.sh  installs on the camera via the device's install-package.sh
```

## Limitations

- **Web‑UI install is not possible on ARTPEC‑4/5.** The UI installer
  (`acapmanager` → `acap-install`) requires the ACAP **≥ 3.0** framework, but this
  hardware's embedded framework is **2.16**, and Axis never ported ACAP 3 to MIPS
  (SDK 3.0.1 dropped the architecture). `upload.cgi` returns `Error: 3`. The
  classic `install-package.sh` (SSH) is the only route — and it's what Axis's own
  classic apps use.
- **Auto‑stop is a real stop.** After 30 min idle the daemon exits and stays
  stopped (by design). Re‑enable from *Apps* or reinstall to use it again.
- **End‑of‑life hardware.** ARTPEC‑4/5 and AXIS OS 9.x are unsupported by Axis as
  of 2025/2026; upgrade to the last available 9.80 LTS for the latest Apache/
  OpenSSL/OpenSSH fixes before exposing a shell tool.

## Security notes

`control.cgi` is protected by the camera's Digest auth (`Require axis-group
admin`). The terminal can reach any host the camera can — only connect to devices
you control on your own network. Passwords and private keys are never logged; the
debug log records only their presence/size and byte counts, never terminal data.
